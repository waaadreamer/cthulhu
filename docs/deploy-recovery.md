# 部署失败恢复与旧版星系首次升级

## 正常入口与恢复入口

网页总览的部署按钮、阿撒托斯 `temple_deploy`、格赫罗斯
`temple_deploy_request` 仍使用同一个部署器；格赫罗斯只能请求阿撒托斯批准。
目标仅来自 GitHub main，旧版/离线星系在 all 作业中明确跳过。

每组在修改代码前持久化原 revision、阶段和更新者。神殿异常重启后会接续
running 作业，重新排空、核对磁盘和认证连接的运行版本；磁盘已经是目标版本
不能替代进程升级确认。正常自重启的 restarting_temple 仍按原流程接续。

重启 RPC 应答丢失时先等待实际认证重连，不能据此认定未执行或立即重复重启。
失败后重新确认排空，回滚磁盘，并确认各 Galaxy 运行旧 revision，才恢复投递。
只有代码没有进入更新阶段的失败才可直接恢复投递。

无法确认回滚（节点离线、检查失败、旧协议不支持回滚等）时：

- 作业标记 failed，步骤和结果消息明确写出“回滚待恢复，保持排空”；不伪报恢复。
- 禁止发起新的发布覆盖未确认状态。
- 主人可在网页点“重新确认回滚”；阿撒托斯可执行
  `temple_deploy(recover_job_id="deploy_...")`。该入口只重试回滚及版本确认，
  不重新部署失败版本，也不会把失败发布改成成功。神殿重启也会重试待恢复回滚。
- 格赫罗斯和其他 agent 不能直接调用该恢复入口，权限仍在服务端执行。

远端明确回滚使用新能力 `deploy_recovery_v1` 的 `deploy_rollback` RPC，
经现有认证 Galaxy 连接传输；当前 HEAD 不是原 revision 或发布目标时拒绝覆盖。
只有 `deploy_v1` 的旧实现不接收未知回滚 RPC，保持排空并报告需要升级/现场恢复。
启动保护仍保留；git 回滚不等于完整依赖环境回滚。依赖变更后的环境故障仍需现场
恢复预先备份的独立环境，不能宣称已自动还原所有包版本。

## 旧版首次升级：不能从中心绕过能力检查

Ali、韩国当前运行进程不支持 deploy_v1。磁盘已暂存 5c67db3 也不代表运行升级，
且该版本本身不含完整自动部署能力。必须由现场维护执行者在独立维护窗口，
把它们首次升级到本修复发布的完整 commit；之后才可统一一键部署。

`deploy/install-galaxy.sh` 是首次安装/配置脚本，会重写 galaxy.json 和 run.sh，
**不要在已有生产星系直接重跑**。不重新 provision、不换 token/agent ID、不删 state。

首次升级的明确顺序（本文件不启动现场操作或新控制器）：

1. 先确认旧手工控制器已退出、门禁撤销、无并行部署作业。现场以自己的 OS 用户
   记录现有源码/解释器/启动器、受管进程身份与独立训练评测的边界；备份代码 revision、
   配置、launcher/unit 和必要的本地环境。凭证始终留原机，不在报告中输出。
2. 在协调者与现场维护执行者都已就位后安排维护窗口。中心用已有 maintenance_drain
   暂停投递；旧agent的safe=false不能当成排空完成。等待实际回合、全部已投递批次结束，
   以运行记录和工具状态证明静默。持久空闲helper不能仅因“有子进程”判为忙，
   也不得直接忽略所有子进程或杀helper伪造静默。
3. 如需停止受管OldOne，仍由黑山羊在明确当次授权内调用既有temple_stop；
   现场 Galaxy 重启必须在其管理单元之外、回合结束后执行，保留训练评测。
   Ali是用户systemd cthulhu-galaxy.service；韩国是已核验的nohup/run.sh监督器，
   两者不能共用未经校验的PID/启动方法。旧等待器不得续签或再次arm。
4. 在干净的既有仓库 `git fetch origin main`，核对完整目标commit属于main，
   用 `git merge --ff-only <完整commit>` 升级，保留未跟踪cthulhu.egg-info。
   仅按依赖差异更新现有独立解释器，检查模块导入；不改共享Conda或个人Codex认证。
   Ali api_provider密钥、CA和provider本地配置原地保留。
5. 由现场执行一次已核验的监督服务重启。通过中心认证连接实证新revision和
   deploy_v1/deploy_recovery_v1；需要时黑山羊恢复同一OldOne，核对新agent drain_v1。
   失败恢复本机备份和原监督服务；无版本确认不得记升级完成。
6. 维护者确认能力、实际业务进程和暂停状态后恢复投递。Provider注册与公司canary
   是单独验收，不由“Galaxy上线”代替。此后所有常规发布走统一部署器。

本次只发布中心可部署组。旧版两地的现场首次升级、离线笔记本重连升级，仍是全量
完成的明确剩余项；all作业显示done不等于这些被跳过目标已经更新。
